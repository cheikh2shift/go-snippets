# systemd WatchdogSec — AI Agent Liveness Experiment

**The problem:** An AI inference agent can hang — waiting on a dead API, stuck in an infinite loop, blocked on a mutex. The process stays alive forever, consuming memory and CPU, doing nothing useful.

**The solution:** systemd's `WatchdogSec` — a kernel-enforced timeout that kills the process if it doesn't "ping" systemd periodically.

## How it works

```
┌─────────────┐     WATCHDOG=1      ┌──────────────────┐
│   go-agent  │ ──────────────────→ │   systemd (PID 1)│
│   (pid=42)  │ ←────────────────── │ "I'm alive"      │
└─────────────┘     every 5s        └──────────────────┘
                                        │
                    If no ping in 30s   │
                    ┌───────────────────┘
                    ▼
            ┌──────────────┐
            │ SIGKILL (9)  │
            │ process dies │
            └──────────────┘
```

The agent must call `sd_notify("WATCHDOG=1")` at intervals shorter than `WatchdogSec`. If it doesn't, systemd sends SIGKILL — no graceful shutdown, no cleanup. This is intentional: a hung process can't respond to SIGTERM either.

## Files

|File|Purpose|
|-|-|
|`main.go`|The AI agent simulation with `--ping-interval` and `--hang-after` flags|
|`go.mod`|Go module with `github.com/coreos/go-systemd` dependency|
|`go.sum`|Checksums (generated by `go mod download`)|
|`ai-agent.service`|systemd unit file with `WatchdogSec=30s`|
|`run.sh`|Convenience script to build, install, and run the experiment|

## Quick start

```bash
# 1. Build
go build -o go-agent .

# 2. Install the systemd unit
sudo cp ai-agent.service /etc/systemd/system/
sudo systemctl daemon-reload

# 3. Run with watchdog active
sudo systemctl start ai-agent

# 4. Watch the logs
sudo journalctl -u ai-agent -f

# 5. Simulate a hang
sudo systemctl stop ai-agent
sudo systemctl start ai-agent -- -hang-after=10s
# After 10s, the agent enters an infinite loop
# After 30s total, systemd kills it
```

## Running without systemd (direct test)

```bash
# Normal run (no hang)
./go-agent

# Hang after 10 seconds
./go-agent -hang-after=10s
# Watch: after 10s it prints "SIMULATING HANG" and loops forever
# No watchdog because NOTIFY\_SOCKET isn't set, so it runs until you Ctrl+C
```

## Running under systemd-run (quick test)

```bash
# With watchdog
sudo systemd-run --scope -p WatchdogSec=30s ./go-agent

# With watchdog + hang simulation
sudo systemd-run --scope -p WatchdogSec=30s ./go-agent -hang-after=10s
# Watch: agent pings for 10s, then hangs, then killed at 30s
```

## Understanding the flags

|Flag|Default|Description|
|-|-|-|
|`-ping-interval`|5s|How often to send `WATCHDOG=1`. Must be < `WatchdogSec`.|
|`-hang-after`|0s|After this many seconds, enter an infinite loop (simulates a hung agent).|
|`-notify-socket`|auto-detect|systemd notify socket path (auto-detected from `NOTIFY\_SOCKET` env var).|

## Why this matters for AI agents

AI inference agents are the perfect candidate for watchdog:

1. **They call external APIs** — Ollama, OpenAI, HuggingFace. These can hang or be slow.
2. **They process large files** — loading a 7B model can take minutes.
3. **They run long loops** — token generation is inherently sequential.
4. **They can deadlock** — concurrent Go goroutines waiting on channels or mutexes.

Without a watchdog, a hung agent is a zombie. With a watchdog, it's automatically restarted, and the failure is logged in the journal.
