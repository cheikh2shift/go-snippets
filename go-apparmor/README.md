# Go + AppArmor Confinement Experiment

This experiment demonstrates how AppArmor can be used to confine a Go
program — including one generated by an AI coding agent — and enforce a
security policy at the kernel level.

## What It Does

The Go binary (`main.go`) exercises several categories of system access:

| Category | Action | Expected under tight profile |
|---|---|---|
| Filesystem | Read `/etc/hostname` | Allowed |
| Filesystem | Read `/etc/shadow` | **Denied** |
| Filesystem | Write `/etc/apparmor-test-marker` | **Denied** |
| Network | Outbound HTTPS to `example.com` | **Denied** |
| Process | Spawn `/bin/ls` | **Denied** |
| Capabilities | Read `/proc/self/status` | Allowed |

The companion profile (`go-apparmor`) defines exactly what is permitted.
Every access not explicitly allowed is denied and logged by the kernel.

## Files

| File | Purpose |
|---|---|
| `main.go` | Go program that probes filesystem, network, process, and capabilities |
| `go-apparmor` | AppArmor profile (text policy file) |
| `install.sh` | Installs the binary and loads the profile |
| `run.sh` | Runs the experiment with the profile active |

## Setup

```bash
# 1. Install AppArmor tooling (Debian/Ubuntu)
sudo apt update
sudo apt install apparmor apparmor-utils

# 2. Build the Go binary
cd go-apparmor-experiment
go build -o go-apparmor main.go

# 3. Install the binary to a path the profile expects
sudo cp go-apparmor /usr/local/bin/go-apparmor

# 4. Install and load the profile
sudo cp go-apparmor /etc/apparmor.d/go-apparmor
sudo apparmor_parser -W /etc/apparmor.d/go-apparmor
sudo systemctl restart apparmor

# 5. Run the experiment
sudo aa-exec -p go-apparmor -- /usr/local/bin/go-apparmor
```

## Observing Denials

AppArmor logs denials to the kernel audit log. Watch them in real time:

```bash
sudo journalctl -kf --grep=apparmor
```

You should see entries like:

```
apparmor="DENIED" operation="open" profile="go-apparmor" name="/etc/shadow" ...
apparmor="DENIED" operation="network" profile="go-apparmor" family="inet" ...
```

## Why This Matters for AI-Generated Code

An AI agent can generate a Go program that reads sensitive files, opens
network connections, or spawns shells — all perfectly legal Go, all
dangerous. AppArmor provides a **defense-in-depth layer** that doesn't
trust the code's provenance. Whether hand-written or agent-generated,
if the binary path matches a profile, the kernel enforces the policy.

This is especially relevant for AI coding agents running with elevated
privileges: even if an agent writes a `curl` call or a `os/exec` command,
AppArmor can deny it before it reaches the kernel.

## Modifying the Profile

To allow more access, edit `go-apparmor` and reload:

```bash
sudo apparmor_parser -r /etc/apparmor.d/go-apparmor  # reload
```

To put the profile in complain mode (log but don't deny):

```bash
sudo aa-complain go-apparmor
```

To return to enforce mode:

```bash
sudo aa-enforce go-apparmor
```
